Cage motion ideas

Four ways to make "every agent gets a cage" move. Each one animates a real sandbox behaviour, so the motion explains the product instead of decorating it. All four use the same tokens and components as the combined directions, so any of them drops into Combo A, B, C or D.

Cage 1 · storytelling

Cage Lifecycle

One cage, five states. OCI layers drop in, the bars build one at a time while a counter runs to 180 ms, the agent works, then lunges at the bars, which rattle and hold with an EPERM spark. Finally the cage falls apart and only the git branch slides out.

motionstate machine with staggered bar build, lunge and rattle keyframes, falling bars, synced log

Cage 2 · security made visible

Cage Firewall

Each call the agent makes is a dot. Allowlisted traffic (github.com, pypi.org, /work) passes through green gates in the bars; mount(), ptrace and curl evil.sh bounce off with sparks. A live ALLOW/DENY feed and counters sit alongside, and one button simulates a prompt-injection burst.

Cage 3 · multi-agent at scale

Cage Rack

The multi-agent TUI as a rack of live cages. Each one shows its own CPU sparkline and changing log line. A new cage builds its bars in with a boot bar; killing one slams the bars shut, shakes it and removes it while the rack reflows smoothly. Click a cage to expand it.

motionFLIP reflow, bar build and slam, live sparklines, auto spawn/kill when idle

Cage 4 · hands-on

Cage Configurator

Drag an agent into an empty cage: the bars drop with a bounce and a boot ring fills. Drag images, MCP servers and skills onto it and they scan through the bars. Unsafe items like docker.sock or host-shell get rejected, the cage shakes and the token flies back. The nanosb run command updates live.

motionpointer drag, bouncy bar drop, scan-through, reject + fly-back, click/keyboard fallback
